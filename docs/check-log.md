Формат: дата · что проверяли · результат · что исправили. Пароли и содержимое `.env` сюда не пишутся.

## 2026-10-15 — сборка этапов 2–7 (ИИ-агент по spec.md, design.md, AGENTS.md, Plan.md)

### Окружение

- PostgreSQL 18.6 (Postgres.app), Node 24.19, Next.js 16.4.0 (Turbopack), Prisma 6.19.3.
- `next/font/google` (Cormorant Garamond, Manrope) при сборке загрузился — запасные стеки из `design.md` оставлены в `--font-display`/`--font-sans` на случай офлайн-сборки.
- `npm run db:reset` (`prisma migrate reset --force`) **не запускался**: Prisma 6.19 блокирует `migrate reset`, если команду запускает ИИ-агент, и требует явного согласия пользователя. Подставлять согласие от имени пользователя агент не стал. Вместо этого:
  - чистое применение миграций проверено на служебной базе `verde_marea_shadow`, которую Prisma сама пересоздаёт при `migrate diff`: миграции → seed ×2 → `check:rules` (105/105), после чего схема shadow-базы снова очищена;
  - основная база `verde_marea` была пустой — к ней применены миграции неразрушающим `npm run db:deploy`, затем `npm run db:seed` ×2.
  Человеку в своём терминале `npm run db:reset` доступен как обычно.

### Что покрывает `check:rules` (105 проверок)

Seed (8 столов 2–8 мест, все роли, все 5 статусов, закрытия, bcrypt-12 у всех); auth (регистрация `$2b$12$`, `bcrypt.compare`, дубль почты, CHECK почты и имени, сессия хранит только SHA-256, срок 7 дней, просроченная удаляется); окна (6 окон по 90 минут до 21:00, понедельник, начавшееся окно ровно в момент начала, вчера, горизонт +13/+14, совпадение набора дней БД и `bookableDates()`, время вне расписания, гости 0/9); закрытия (окно, день, дубли, прямая вставка дубля, понедельник/горизонт/время/пустая причина, права user, открытие и повторное открытие, удаление в обход функции без автора, закрытие не трогает бронирования); создание (pending, порядок столов T1,T2,T6,T3, показ назначаемого стола, второе активное у пользователя — функцией и прямой вставкой, один стол на окно — прямой вставкой, вместимость/90 минут/гости/неактивный стол/автор при прямой вставке, неактивный стол не назначается, нет стола, **гонка двух параллельных запросов на последний стол**, отмена освобождает стол, AuditLog+Notification, составной FK уведомления); дедлайн отмены (ровно за 3 ч — можно, за 2:59 — нет, чужое — нет, admin до начала — можно, после — нет, запись в историю); переходы (все 25 пар статусов × «до начала»/«после начала» для admin со сверкой с `staffTransitions()` и проверкой истории `{from,to}` и уведомления; super_admin; user не подтверждает/завершает; терминальные статусы и недопустимые переходы прямым UPDATE; неизменяемые поля; UPDATE без автора); роли (матрица `lib/permissions.ts` = таблица spec.md раздел 6 для всех 11 прав × 4 субъекта; повышение/понижение с историей; admin и user не меняют роли; super_admin защищён в функции и триггером от UPDATE/INSERT; та же роль; смена роли в обход функции без автора; права в permissions.ts совпадают с ответом БД); уборка (данные seed не изменились).

## 2026-10-15 — этап 8: доработки перед сдачей (обновлённые spec.md, раздел 4 и 8; AGENTS.md; Plan.md)

### Что изменено

- **Переходы `pending` после начала окна** (spec, раздел 4). Правило изменено сразу в трёх местах:
  `lib/booking/rules.ts` (`STATUS_TRANSITIONS`, новая `staffCanTransition`) → новая миграция
  `20261015180000_pending_after_start` (`CREATE OR REPLACE` триггера `vm_booking_before_write` и функции
  `vm_change_booking_status`; применённые миграции не тронуты) → кнопки `/admin` (строятся из `staffTransitions`).
- **Плашка «Ваша роль»** в административном контуре и пояснение для admin на «Пользователях» (spec, раздел 8) —
  по той же матрице `lib/permissions.ts` (`describeRole`, `PERMISSION_LABELS`).
- **Фиксированные демо-пароли.** Учебные значения в `.env.example`. В локальном `.env` заменены только четыре строки `SEED_*`,
  строки `DATABASE_URL` и `SHADOW_DATABASE_URL` не тронуты. Seed теперь обновляет пароль и имя уже существующих демо-пользователей
  (у владельца пароль обновлялся и раньше). Добавлен пример «pending после начала окна».
- **README переписан для проверяющего:**
  - функционал по ролям и все экраны;
  - таблица демо-аккаунтов;
  - требования;
  - запуск на macOS, Linux и Windows;
  - назначение каждой команды;
  - сценарий проверки из 18 шагов;
  - таблица «требование → код → как проверить»;
  - правила окон и машина состояний;
  - частые проблемы и ссылки на документы.
- **`.gitignore`** дополнен (`.claude/`, `*.log`, временные файлы, IDE). Проверка на копии структуры:
  в индекс попадают только исходники, миграции, документация и `.env.example`. Не попадают `.env`, `node_modules`, `.next`,
  `*.tsbuildinfo`, `next-env.d.ts`, `.backups/`, `.claude/` и `*.log`.
- `check:rules`: новые проверки «pending после начала: completed / no_show / cancelled», «confirmed после начала не
  отменяется, pending до начала не завершается», «владелец не отменяет pending после начала». Матрица из 25 пар
  сверяется с новой `staffTransitions()`. `check:http`: вход демо-гостей по паролю из README, плашка роли, пояснение
  на «Пользователях», кнопки у прошедшего `pending`, уборка выданных сессий.
